= Getting Started with {productName}

== What is Payara Qube?

Payara Qube is an enterprise-grade platform for deploying Jakarta EE, Spring Boot, and Quarkus applications.
It simplifies deployment by automating infrastructure provisioning and removing the need to manually manage application servers, containers, and Kubernetes clusters.

The {productName} Console provides a simple, guided interface for configuring applications and their runtime, with comprehensive CLI tools available for automation.

== Consumption Models

Payara Qube is available in two consumption models:

* **Payara Qube (Managed)**: A fully managed service where Payara hosts and operates the platform infrastructure. Your team can focus entirely on application development without operating the underlying infrastructure.
* **Payara Qube**: A self-hosted platform that you install and run on your own Kubernetes infrastructure, giving you complete control over your environment, data, and security.

ifeval::["{page-site-edition}" == "cloud"]
This guide covers getting started with **Payara Qube (Managed)**, the fully managed service.
endif::[]

ifeval::["{page-site-edition}" == "qube"]
This guide covers getting started with **Payara Qube**, the self-hosted platform.
endif::[]

== Supported Application Types

{productName} supports three major application frameworks:

* **Jakarta EE/MicroProfile applications**: Deployed as WAR files, supporting Jakarta EE 8 (Payara 5) and Jakarta EE 10 (Payara 6)
* **Spring Boot applications**: Deployed as JAR files with full Spring Boot configuration support
* **Quarkus applications**: Deployed as ZIP files with native Quarkus configuration support

== Installing Payara Qube (Self-Hosted)

=== Prerequisites

Before starting the installation, ensure you have:

* AWS CLI client configured with appropriate administrative permissions
* Access to your Nexus credentials (provided in your welcome package)
* https://www.pulumi.com[Pulumi] installed on your machine
* npm and Helm (may be required depending on your system)

=== Installation Overview

Payara Qube installation uses Pulumi for infrastructure management and deploys on AWS. The process typically takes approximately 45 minutes.

=== Get Installation Files

. Navigate to https://billing.payara.cloud/install-qube/wizard as instructed in your welcome package
. Enter your Nexus credentials when prompted
. Define a name for your installation (this will prefix all AWS resources)
. Configure DNS settings:
  * **Control Plane Domain**: `stackName.control.example.com`
  * **Control Plane Zone**: `control.example.com` (must exist in your AWS account)
  * **Application Domain**: `stackName.apps.example.com`
  * **Application Zone**: `apps.example.com` (recommended to exist in your AWS account)
  * **LetsEncrypt Contact Email**: Your email for SSL certificate notifications
. Review SMTP provider settings
. Review default instance settings (avoid instances smaller than 2-CPU)
. Set your Region ID and Region Description
. Click **Generate installation data** to download the installation package

=== Configure Pulumi

Choose your state management backend:

* **Pulumi Cloud** (recommended): Secure online service for team collaboration
* **S3 bucket**: Store state in AWS S3 or other cloud storage
* **Local storage**: Not recommended for production

Authenticate with Pulumi:

[source,bash]
----
# For Pulumi Cloud
pulumi login

# For Azure Blob storage
pulumi login azblob://pulumi/?storage_account=stacc

# For local storage (not recommended)
pulumi login --local
----

=== Deploy Infrastructure

. Extract the installation files to a directory
. Initialize the Pulumi stack:
+
[source,bash]
----
pulumi stack init your-stack-name
pulumi refresh -y
----

. Install Pulumi SDK:
+
[source,bash]
----
pulumi install
----

. Start deployment:
+
[source,bash]
----
pulumi up
----

The deployment will show a preview and wait for confirmation before executing.

NOTE: Due to eventually consistent nature of Kubernetes and AWS, you may need to run `pulumi up` multiple times if initial attempts encounter timing issues.

=== Configure DNS

If both parent domains were in your AWS account, DNS configuration is automatic. Otherwise:

. Check AWS Route 53 console for your hosted zone details
. Note the nameservers for your application domain
. Create NS records in the parent domain pointing to these nameservers

The installation will not complete until domains resolve publicly.

=== Post-Installation Setup

. View installation outputs:
+
[source,bash]
----
pulumi stack output --show-secrets
----
+
This displays:
  * `userManagementUrl`: Keycloak admin interface
  * `managementUrl`: Payara Qube management interface
  * `userManagementAdminUser` and `userManagementAdminPassword`: Initial admin credentials

. Configure Keycloak Administrator:
  * Visit the `userManagementUrl` with admin credentials
  * Create a permanent admin account
  * Navigate to **Users** > **Add User**
  * Set username and password
  * In **Role Mapping**, assign the admin role
  * Optionally disable the initial admin account

. Create Your First Organization:
  * Navigate to the `managementUrl`
  * Log in with organization admin credentials
  * Click to create a new organization
  * Add users by specifying their email addresses

For detailed installation instructions, see the xref:ROOT:getting-started/qube/qube-installation.adoc[Installation Guide].

=== Key Features

* Complete infrastructure control
* Built-in horizontal scaling
* Built-in monitoring and logging
* Custom domain support
* SSL/TLS certificate management
* Self-hosted on your own Kubernetes infrastructure

=== Prepare Your Application

Ensure you have an application ready in one of the supported formats:

* **Jakarta EE/MicroProfile**: WAR file
* **Spring Boot**: JAR file
* **Quarkus**: ZIP file (see link:../user-guides/common/application/Building-Quarkus-Applications.html[Building Quarkus Applications] for instructions)

TIP: If you need a demo application, check out the https://github.com/Jakarta-EE-Petclinic/petclinic-jakartaee[Jakarta EE 10 version of Pet Clinic].

=== Access Your Namespace

ifeval::["{page-site-edition}" == "cloud"]
. Log in to your {productName} account
. You'll be directed to the Namespaces screen
. A default namespace called `start-dev` is pre-created for you
endif::[]

ifeval::["{page-site-edition}" == "qube"]
. Log in to your {productName} instance
. Navigate to your organization
. Create or select a namespace for your application
endif::[]

=== Upload and Deploy

. From the Namespace Details screen, click **Upload Application**
. Select your application file (WAR, JAR, or ZIP)
. If your application doesn't require special configuration:
  * Check the **Deploy Immediately** checkbox
  * Click **Upload**
. If your application needs configuration:
  * Upload without deploying
  * Configure settings on the application detail screen:
    - MicroProfile Config properties
    - Context root
    - Database connections
    - Runtime size and scaling options
  * Click **Application Actions** > **Deploy Changes**

=== Access Your Application

After successful deployment:

. The application status will update to **Running**
. Click on the **Application URL** to access your application
. Note: There may be a slight delay due to DNS propagation

== Core Concepts

=== Namespaces

A namespace groups applications under a single domain, with each application having its own path prefix. Namespaces provide:

* Logical separation of applications
* Shared domain configuration
* Custom domain support
* Isolated environments (dev, test, prod)

=== Applications

Applications are your deployed services. Each application:

* Has its own configuration
* Can be scaled independently
* Has dedicated monitoring and logging
* Supports multiple revisions

=== Revisions

Every deployment creates a new revision. Revisions allow you to:

* Track deployment history
* Rollback to previous versions
* Compare configurations between deployments
